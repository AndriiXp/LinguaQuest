# LinguaQuest

Приложение для изучения английского в игровой форме (iOS 17+, SwiftUI + SwiftData).
Реализованы **Спринт 0** (фундамент) и **Спринт 1** (ядро уроков) из ТЗ — Фаза 1, всё локально и офлайн.

## Что уже работает

- Дерево навыков с разблокировкой по предпосылкам и коронами освоения (0–5)
- Движок урока: `multiple_choice`, `type_answer`, `match_pairs`
- Система жизней с восстановлением по времени, прощение опечаток, возврат проваленных заданий в очередь
- Экран итогов: XP, монеты, точность, разбор ошибок
- XP → уровни персонажа, дневная цель, streak с автосписанием заморозок
- Аватары (SF Symbols + градиенты): открываются по уровню или покупаются за монеты/кристаллы
- SwiftData-хранилище: профиль, прогресс, ошибки, карточки SRS
- Карточки интервального повтора (SM-2) создаются из пройденной лексики уже сейчас
- Контент A1: 3 навыка, 7 уроков, 51 задание, 41 слово — сгенерирован по CEFR / Oxford 3000 / NGSL

## Сборка без Mac (основной путь)

Mac не нужен: собирает GitHub Actions на облачном macOS, приложение ставится на iPhone
с Windows через Sideloadly. Пошаговая инструкция — **[`Docs/deploy-to-iphone.md`](Docs/deploy-to-iphone.md)**.

- `.github/workflows/ci.yml` — на каждый push: валидация контента, тесты, сборка. Ошибки компиляции видны здесь.
- `.github/workflows/ipa.yml` — по кнопке: неподписанный `.ipa` в артефактах.

## Сборка на Mac (если появится)

Проект описан в `project.yml` — файл `.xcodeproj` генерируется, а не хранится в git.

```bash
brew install xcodegen   # один раз
make generate           # создаёт LinguaQuest.xcodeproj
make open               # открывает проект в Xcode
```

Дальше в Xcode: выбрать симулятор iPhone → ⌘R.
Для запуска на устройстве укажите свою Team в настройках таргета (Signing & Capabilities).

## Тесты

```bash
make test        # xcodebuild test на симуляторе
make check       # валидация контента + референсные алгоритмы (работает и без Mac)
```

- `Packages/LinguaQuestKit/Tests` — XCTest на движок урока, SM-2, кривую уровней, streak, сердца, загрузчик контента
- `Tools/reference_algorithms.py` — те же формулы на Python с тестами; ожидаемые значения синхронизированы с XCTest
- `Tools/validate_content.py` — проверка JSON-контента по тем же правилам, что применяет `ContentCatalog`

## Структура

```
project.yml                    описание Xcode-проекта для XcodeGen
App/                           таргет приложения (только UI и композиция)
  LinguaQuestApp.swift         точка входа, поднятие зависимостей
  RootView.swift               вкладки и маршруты
  Features/                    экраны по фичам
Packages/LinguaQuestKit/       вся логика в виде Swift-пакета
  Sources/Core/                дизайн-токены, навигация, правила игры, аватары
  Sources/ContentModels/       модели контента + загрузчик + bundled JSON
  Sources/LessonEngine/        стейт-машина урока, валидация ответов, сердца
  Sources/SRSEngine/           алгоритм SM-2
  Sources/Persistence/         SwiftData-модели и GameStore
  Sources/UIComponents/        переиспользуемые SwiftUI-компоненты
Tools/                         валидатор контента и референсные алгоритмы
Docs/                          пайплайн генерации контента, решения по архитектуре
```

Разделение сделано так, что вся игровая логика тестируется без UI и без базы:
`LessonSession`, `SM2Scheduler`, `StreakCalculator`, `Progression`, `HeartsState` — чистые типы,
принимающие время и случайность параметрами.

## Ключевые решения

| Вопрос | Решение | Почему |
|--------|---------|--------|
| Формат Xcode-проекта | XcodeGen (`project.yml`) | Нет конфликтов в `.pbxproj`, проект воспроизводим |
| Модули | Один локальный SPM-пакет с шестью продуктами | Границы модулей соблюдены, но не нужно шесть отдельных репозиториев |
| Аватары | SF Symbols на градиентах | Нет ассетов, нет вопросов по правам, идеальное масштабирование |
| Backend (Фаза 2) | Firebase, но за протоколом `ContentSource` | Замена на Supabase не затронет приложение |
| Монетизация | Первый релиз без StoreKit | Экономика (`GameRules`) уже вынесена в один тип и готова к Remote Config |
| Контент | Оригинальный, по открытым стандартам | Копирование из учебников недопустимо — см. `Docs/content-pipeline.md` |

## Известные ограничения

- **Локализация не начата.** ТЗ (§8) требует String Catalog с ru + en; сейчас строки интерфейса
  захардкожены по-русски, а `UserSettings.interfaceLanguage` пока ни на что не влияет.
  Это работа Спринта 8 (полировка перед стором) — до неё поле оставлено как задел для схемы.
- **Речь и аудио** (`listening`, `speaking`, TTS) — Спринт 4. Задания этих типов можно писать
  в контенте уже сейчас: загрузчик их отфильтрует.
- **Экран Review** — заглушка со счётчиком; сами карточки SRS уже создаются и планируются.

## Что дальше по ТЗ

- **Спринт 2** — визуальное дерево-путь, ачивки, экран профиля с календарём активности
- **Спринт 3** — экран Review (карточки уже накапливаются), типы `word_order` и `fill_blank`
- **Спринт 4** — TTS, listening, speaking через Speech framework, локальные уведомления
- **Фаза 2** — Firebase, лиги, адаптивная генерация через Claude API, StoreKit

Нереализованные типы заданий не нужно «выключать» руками: `ExerciseType.isImplemented`
фильтрует их при загрузке, поэтому контент можно писать заранее.
